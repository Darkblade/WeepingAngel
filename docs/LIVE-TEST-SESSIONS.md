# Live test sessions

Open Devices → LAN devices → Live test session. Start router monitoring separately. Enter a test name and select Start test session. Test logging does not start router capture, change motion settings, or trigger cameras.

The default folder is `%LOCALAPPDATA%\DontBlink\diagnostics`. Copy log path points to `current.jsonl`. `session.json` identifies the session and its rolling files. Records flush as they are written, so another process can tail the current file while the app runs. Open readers with FileShare.ReadWrite | FileShare.Delete; reopen current.jsonl after rotation. PowerShell `Get-Content -LiteralPath <path> -Tail 100` is suitable for repeated reads. The assistant can read these local files through tools during an active chat turn; there is no permanent chat connection or remote upload.

Only one test session runs at a time. A new session replaces the previous session's files. Stop and copy the folder elsewhere first if it should be preserved. Four rolling JSONL segments retain approximately 20 MiB total. Oldest first: previous-3, previous-2, previous-1, current. Sequence gaps can mean old segments rotated away or queue overflow. The UI and session_end report the number of records dropped by the bounded 8192-entry writer queue. Packet processing never waits for disk I/O. Write failures stop logging and appear in the session status, without stopping monitoring.

Schema version 1 records have sessionId, sequence, recordedUtc, optional observedUtc, kind and data. Timestamps include UTC offsets. Packet records contain IPv4 TCP/UDP endpoint addresses, ports, packet/payload lengths, configured source/destination identity (IP and MAC checked), TCP flags, sequence and acknowledgement. No raw frame/payload, TLS content, router credentials or authorization tokens are written. IPv6, fragmented IPv4 and other link/protocol types are currently omitted. Router filters and interface visibility can limit what is observed. Byte counts in packet records include retransmissions; inferred activity summaries use the existing deduplicated classifier.

Inventory records include LAN devices and explicit Guard Post camera links. Monitor records capture source health, freshness, per-camera state and inferred activity once per second, including idle periods. Action records mark Windows/phone image and motion commands plus live-view requests/end. Command completion is distinct from independently verified physical behavior. Use Mark test event for physical motion: enter a camera and action, then mark immediately when it occurs. Manual text is stored as entered (control characters removed, limited to 300 characters); enter test descriptions only.

Recommended protocol: log an idle baseline, let the assistant inspect the tail, perform one requested action, mark it or reply done, and inspect the next entries. Capture the baseline and action in the same session. Stop test session flushes all queued records; stopping router monitoring alone leaves the test session running to record its stopped state. Closing the app flushes the session as part of shutdown.
